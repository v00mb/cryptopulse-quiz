CryptoPulse: from quiz to first alert

How the funnel works, why each step is there, and how I would measure it. The clickable version is in the Prototype tab.

01Executive summary

CryptoPulse is a concept for a crypto market monitoring service. It helps people track the assets they choose and understand market changes through personalized alerts in Telegram.

The funnel's goal is more than collecting answers. It should help the visitor understand which monitoring setup fits their needs, and give them a reason to start using the product.

User problem

People who are just getting into crypto can run into information overload: countless assets, charts, indicators and constant price changes. More experienced users need specific alerts without having to check the market by hand.

HypothesisThis is an initial product hypothesis. It still needs to be checked with user research.

Active watchers still get a basic result (simple price levels), so nobody finishes the quiz at a dead end, and their share of completions shows when the segment is worth building for.

02First screen: quiz-first landing page

The quiz is the centre of the landing page, not an extra step after a long landing page. The first screen has one job: get the visitor to start the quiz.

Value proposition
Spend about a minute and get a personal crypto monitoring setup.
Headline
“Follow crypto without watching charts all day.” It speaks to both MVP segments: beginners want to understand the market, casual followers want to stop checking it.
Primary CTA
Find my setupThe quiz starts in place, on the same page.
Trust line
No exchange login or API keys, no deposits, no email needed to see the result. For a crypto audience, a request for exchange access is a strong trust barrier, so the screen rules it out before the first click.
Visual
A noisy feed of price changes next to three calm example messages: the problem and the outcome side by side.

HypothesisInstead of an abstract call to sign up, the visitor is offered a concrete result that matches their interests. That could raise the start rate, but it is a hypothesis, not a proven effect (see section 06).

One deliberate choice: no email gate before the result. Many quiz funnels ask for an email to unlock the result. Here the conversion that matters is opening the bot, and a gate would add a step and a reason to leave right before it. If email becomes useful later, it can be an optional field on the result screen and an A/B test.

03Quiz: 7 questions

The quiz identifies the user's monitoring need, not their personality. Every answer has to change something in the recommendation or the setup. An answer that changes nothing only creates an impression of personalization, and that question should go.

Questions 1 to 5 follow the original logic. I added 6 and 7 for the steps after the quiz: question 6 prefills the watchlist so the setup in the bot takes fewer taps, and question 7 lets the result screen answer the user's main concern right next to the CTA.

How the recommendation is calculated

  1. Each answer gives 0 to 2 points to one or more of the three setups.
  2. Points are multiplied by the question's weight. Motivation (×3) counts the most, then data type (×2) and expected value (×1.5).
  3. The setup with the highest total wins. Ties go to the simpler setup (Market Basics, then Watchlist Pulse, then Price Level Alerts), in line with the MVP focus.
  4. Questions 2, 3, 4, 6 and 7 also set details of the setup: how much messages explain, the main feature, delivery, coins and the reassurance message.

04Result, final CTA and the move to Telegram

After seeing the result, the user should understand exactly what they get when they tap the button.

What the result screen shows

  • The setup and a one-line promise, for example “Watchlist Pulse: your coins on a watchlist, and a message only when something important happens.”
  • What you'll get: coins, trigger, delivery, explanation level and main feature, each set by a specific answer.
  • Why this setup: the user's own answers quoted back, the ones that weighed most.
  • A preview of a real message written at the user's explanation level, so the value is visible before the click.
  • An answer to the concern from question 7, placed right before the CTA.
  • The CTA with the next steps written next to it: “Open my setup in Telegram.”
  • A way out: switch to another setup or retake the quiz. How often people switch tells us whether the scoring is right.

What happens after the CTA

  1. The user opens the Telegram bot through a link with a parameter that carries the ID of their recommendation.
  2. The bot explains the recommended setup and asks which coins to watch.
  3. The user sets price thresholds or picks a summary format.
  4. The bot confirms the settings and switches monitoring on.

The prototype simulates this conversation, including a sample first alert.

Deep link

https://t.me/<bot_username>?start=wp-std-big-btc-eth

Telegram passes the start parameter to the bot together with the /start command. It allows up to 64 characters: Latin letters, digits, underscore and hyphen. In the prototype the code describes only the setup (setup, explanation level, delivery, coins). Personal or sensitive data never goes into the URL.

For production I would switch to a short random ID, for example r_k3f9x2, that points to the stored quiz result. The link then means nothing to anyone who sees it, and web analytics can be joined to bot events, so the whole funnel from landing to activation is measurable.

Key point. Opening Telegram is an intermediate conversion, not full activation. The user gets real value only after setting up monitoring and starting to receive relevant alerts. That is why the bot onboarding counts as part of the funnel and is measured the same way as the quiz.

Desktop visitors

On desktop, a t.me link opens Telegram Desktop or the web version. The result screen should also show a QR code, so the user can continue on their phone, where alerts are most useful.

07Risks and guardrails

  • Not financial advice. CryptoPulse sends market data and alerts, never buy or sell signals. The copy avoids promises of profit and “don't miss out” pressure, and the bot says so when monitoring starts.
  • Trust and security. No exchange login, API keys, wallet connection or deposits at any step. This is stated on the first screen and next to the final CTA.
  • Privacy. The deep link carries only a setup code or a random ID. Analytics run on anonymous IDs.
  • Notification fatigue. Frequency caps, quiet hours on by default, one-tap pause. A muted bot is a lost user, so the mute rate is watched as closely as activation.
  • Channel dependency. Everything runs through Telegram. If many visitors don't use it (the bot start rate will show it), an email digest is the fallback to test.
  • Data quality. Every alert shows its price source and time, so users can check it.

08How AI was used

I used AI as a working partner: I set the direction and the constraints, and the AI expanded them and built the prototype.

My decisions

  • The product concept and the problem hypothesis
  • Three audience segments and the MVP focus on the first two
  • The funnel shape: quiz-first landing, result, Telegram as the activation channel
  • The logic of questions 1 to 5: what each one measures and how it is used
  • Constraints: no exchange login, API keys or deposits; no personal data in the link; every hypothesis labelled as one

What the AI did (Claude)

  • Expanded the brief into the full question set, including questions 6 and 7 and all answer options
  • Proposed the scoring model, the weights and the tie-break rule
  • Wrote the interface copy and the sample bot messages
  • Built this page: the clickable quiz, the result logic, the Telegram bot simulation and the reviewer notes
  • Drafted the metrics, the test plan and the risk list from the brief

The rule I gave the AI is the same one I use to review its work: the quiz measures needs, not personality, and an answer that changes nothing gets cut.
